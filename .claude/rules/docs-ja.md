# 人が読む文書の文体

README と docs/ は人が読む(合流した開発者、利用者、採用担当、半年後の自分)。AGENTS.md、.claude/、PR と Issue のテンプレート、docs/lessons/ は AI が読む。2つの文体を分ける。

人が読む文書(README はですます調。docs/ は常体のまま。AI のために書いている部分もあるので、文体の書き換えだけを目的に docs/ を直さない。2026-10-07 メンテナ):

- 主語と述語を揃える。誰が何をしたかが、その文の中で分かるように書く。
- 1文に1つのこと。目安は 30〜45 字、読点は 0〜2 つ。長い文は分ける。
- 「〜。〜。」と語を並べる断片や、括弧の中に補足を詰めた文は使わない。補足は文で言う。
- 「→」「=」「:」「――」で文を代用しない。接続は「ので」「が」「とき」で、文の中でつなぐ。
- 道具や概念を人のように動かさない(「設計が語る」「hook が守ってくれる」)。操作として書く(「hook が止める」)。
- 比喩の動詞は日常の動詞にする(「壊れる」→「失敗する」、「溶かす」→「一つにまとめる」)。
- 太字は結論の語に1箇所まで。箇条書きの各項目に「見出し語:」を機械的に付けない。
- 三つ組の強制、定型の結び(「〜が重要です」「今後の展望」)、意義の強調、過剰な断定の弱め(「〜かもしれません」の連発)をしない。
- 専門語は初出で一言の説明を文の中に入れる。数字は表か箇条書きに置き、文の中に並べない。
- 見出しの直下に、その節で何が分かるかを1〜2文で書く。「なぜ」を先に、「何を」をその後に。
- 既にある文を書き直すときは、主張、強調、断定の強さ、文の役割(説明か指示か)を変えず、情報を足さない。

AI が読む文書(AGENTS.md、.claude/rules、テンプレート、lessons):

- 短く、具体的に、1行1指示。理由は1語か1句で添える。常体。

この原則は、AI の書く日本語を自然に直す公開 skill「yomiyasu」(nanaism、MIT)の7原則と、m0370 の「AIくささ」16項目から、この repo に合うものを選んだ。迷ったら、その文を声に出して読み、人に説明しているように聞こえるかで判断する。

# /pr

本文のうち「何を変えたか、なぜ」はメンテナが書く欄で、AI は書かない(docs/OWNER_WRITTEN.md と同じ扱い)。頼まれても下書きしない。差分の要約を見せるのもこの欄を書く前にはしない(見せると自分の言葉でなくなる)。

1. 差分を読む。`git log main..HEAD --oneline`、`git diff main...HEAD --stat`。push していなければ先に push する。
2. メンテナに「何を変えたか、なぜ」を書いてもらう。1〜3 文でよい。入力をそのまま本文に入れる(言い換えない、整えない)。空のままなら PR は出さない。
3. 残り2つを差分から下書きする。「どう確かめたか」は、このセッションで実際に走らせたテストと確認した CI の結果だけ(走らせていなければ「未確認」)。「AI と人の分担」は git log の著者と直近の HANDOFF の「使ったモデル」の行から。
4. メンテナの文と差分を突き合わせ、食い違い(差分に無いことを言っている、差分にあることを言っていない)があれば、送る前に1つずつ示す。直すのはメンテナ(説明を直すか、理解を直すか)。
5. 了解を得てから出す。本文を一時ファイルに書き、`gh pr create --title "<件名>" --body-file <ファイル>`。gh が無ければ、タイトルと本文を貼れる形で出して終わる。
6. 出たら PR 番号で docs/AI_USAGE.md の表に1行足し、`uv run tools/commit.py "AI_USAGE: #<番号>" docs/AI_USAGE.md` でコミットして push する。
7. 最後に PR の URL と、`/review-pr` の案内を1行。

# Unity プロジェクトが無いときは test.py を止め、段階を進められるようにする

## 要件

1. tools/test.py は、ルートが Unity プロジェクトでないときに、Unity を起動せずに止まる。何が無いので止めたかを表示する。Unity プロジェクトかどうかは、たとえば `ProjectSettings/ProjectVersion.txt` の有無で判断する。
2. そのとき test.py は、`results/last_test.json` に「Unity プロジェクトが無いのでテストを飛ばした」ことを、その時点のコミットと一緒に残す。「通った」とは区別して書く。
3. tools/status.py は、最新のコミットについて 2 の記録があれば、段階2を終えたものとして扱う。段階の表示や残りには「Unity のテストは飛ばした(Unity プロジェクトが無い)」と出す。Unity プロジェクトがあるのに失敗したり、テストが0件だったりする場合の扱いは、今のまま変えない。

## なぜ

Issue #2 のように環境だけを変えるブランチには、まだ Unity プロジェクトが無い(`Assets/`、`ProjectSettings/`、`Packages/` が無い)。それでも status.py の `tests_ok` は、EditMode と PlayMode の両方が通った記録を求める。そのため、段階が「2 テスト(未実行)」のまま進まない。

今の test.py は、`UNITY_PATH` が未設定なら起動前に止まる。しかし `UNITY_PATH` を設定すると、Unity プロジェクトでないフォルダを `-projectPath` に渡して Unity を起動する。Unity はそこに新しいプロジェクトの雛形を作る可能性がある。そうなると、dev の役割のセッションが Bash 経由で `Packages/manifest.json`(環境の範囲)を書くことになる。これは提案「Bash 経由の書き込み」の穴を通る形でもある。

メンテナは、運用面の修正が済んだら設計を本格的に始め、Unity プロジェクトを作る予定である(2026-10-10 メンテナ)。それまでは、Unity プロジェクトが無いことを普通の状態として扱いたい。

## 確かめたこと(2026-10-10、feat/2-verify-hooks の 5519af8、dev の役割)

- worktree には `ProjectSettings/ProjectVersion.txt`、`Assets/`、`Packages/` が無い。
- 手元には Unity が2つある(`6000.3.18f1`、`6000.5.1f1`)。`UNITY_PATH` は未設定である。
- 段階の表示は「2 テスト(未実行)」で、`tests_ok` が偽なので先に進まない(status.py の `stage_dev`)。
- test.py は回していない。Unity プロジェクトの雛形が作られるおそれがあるためである。

## 実装の重さの見立て

小さい。test.py の `main()` の、`UNITY_PATH` を確かめる箇所の隣に判定を1つ足す。status.py は `tests_ok` と段階2の理由の表示に、飛ばした場合の扱いを足す。テストは tools/tests/ に、隣の `test_test_py_*` と同じ大きさで2〜3件になる見込みである。

## 受け入れの条件

- Unity プロジェクトの無い tmp_repo で、偽の Unity を `UNITY_PATH` に渡して test.py を回したとき、次のようになる。
  - 偽の Unity が起動しない。起動したら印のファイルを書く偽物にして確かめる。
  - 止めた理由が表示される。
  - `last_test.json` に、飛ばしたことと HEAD のコミットが残る。
- その `last_test.json` があるとき、`stage_dev` が段階2で止まらない。
- `ProjectSettings/ProjectVersion.txt` を置いた tmp_repo では、今の `test_test_py_does_not_reuse_old_xml` と `test_test_py_zero_tests_is_not_success` が今と同じ結果になる。

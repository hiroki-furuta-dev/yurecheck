# Bash 経由の書き込みを役割の範囲で止める

## 要件

Bash の命令で、役割の範囲外のファイルに書けないようにする。範囲は Write/Edit と同じ .claude/role_paths.json に従う。

- dev の役割は、env_only のパスに Bash で書けない(`>`、`>>`、`tee`、`cp` の宛先など)。
- 両方の役割とも、owner_written のパスに Bash で書けない。
- env の役割は env_only のパスに Bash で書ける。dev の役割は Assets/ などの自分の範囲に Bash で書ける(止めすぎない)。

## なぜ

Write/Edit は settings の deny と pretooluse_guard.py の両方が止める。Bash には同じ守りがない。AGENTS.md の「settings の deny と Write/Edit の PreToolUse hook の両方が止める」は、Bash からの書き込みには当てはまらない。

## 再現(2026-10-10、feat/2-verify-hooks、dev の役割)

1. Write ツールで `.github/_role_probe.txt` を作ろうとすると止まった。止めたのは settings.dev.json の deny `Write(./.github/**)` だった。
2. Bash で `echo probe > .github/_role_probe.txt` を打っても止まった。ただし repo の仕組みが止めたのではない。同じ入力を `.claude/hooks/commit_gate.sh` に stdin で渡すと `rc=0` で通る。settings にも当たる deny がない。auto mode の判定か人の拒否で止まっただけなので、そこを通れば書ける。

## 受け入れのテスト

tools/tests/ に置く想定(dev は書けないので本文をここに置く)。tools/tests/conftest.py の `tmp_repo` と `run_hook` を使う。2026-10-10 に feat/2-verify-hooks(44e5cd9)で回すと「5 failed, 2 passed」だった。止める側の 5 件が失敗するので、穴を再現できている。通す側の 2 件は今も通る。

Bash の PreToolUse で呼ぶ hook の名前は仮に pretooluse_commit_gate.py にしてある。どこで止めるかは環境の役割が決める。

```python
import pytest
from conftest import run_hook

GATE = ".claude/hooks/pretooluse_commit_gate.py"


def bash(repo, command):
    return {"tool_name": "Bash", "tool_input": {"command": command}, "cwd": str(repo)}


@pytest.mark.parametrize("command", [
    "echo probe > .github/_probe.txt",
    "echo probe >> tools/x.py",
    "echo probe | tee .claude/x.md",
    "cp README.md AGENTS.md",
])
def test_dev_bash_cannot_write_env_paths(tmp_repo, command):
    r = run_hook(tmp_repo, GATE, bash(tmp_repo, command), "dev")
    assert r.returncode == 2


def test_bash_cannot_write_owner_written_for_both_roles(tmp_repo):
    for role in ("dev", "env"):
        r = run_hook(tmp_repo, GATE, bash(tmp_repo, "echo x > docs/METRICS.md"), role)
        assert r.returncode == 2


def test_env_bash_can_write_env_paths(tmp_repo):
    r = run_hook(tmp_repo, GATE, bash(tmp_repo, "echo probe > .github/_probe.txt"), "env")
    assert r.returncode == 0


def test_dev_bash_can_write_assets(tmp_repo):
    r = run_hook(tmp_repo, GATE, bash(tmp_repo, "echo x > Assets/Yurecheck/Runtime/Foo.cs"), "dev")
    assert r.returncode == 0
```

## 範囲の外として残すこと

Bash の文字列からすべての書き込みを見抜くのは無理がある(`python -c`、変数展開、スクリプトの中の書き込み)。.claude/rules/ops.md も Read の deny について同じことを認めている。上の 4 つの形を止めて、残りをどこまで追うかは環境の役割の判断に任せる。

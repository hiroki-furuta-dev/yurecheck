# 書けないファイルの範囲を、書かれている場所どうしで揃える

## 要件

書けないファイルの範囲は2種類あり、どちらも複数の場所に書かれている。種類ごとに、書かれている場所どうしが同じパスの集合を指すようにする。2種類を1つの集合にまとめて比べると、役割の分け方が崩れるので、混ぜない。

メンテナが書くファイル(どちらの役割も書けない):

- docs/OWNER_WRITTEN.md の表
- .claude/role_paths.json の owner_written
- .claude/rules/owner-written.md の paths
- .claude/settings.dev.json と settings.env.json の deny のうち、メンテナが書くファイルの分

環境の範囲(dev の役割だけが書けない):

- .claude/role_paths.json の env_only
- .claude/settings.dev.json の deny のうち、メンテナが書くファイルの分を除いたもの

今は次の2点が食い違っている。

1. メンテナが書くファイルの食い違い。owner-written.md の paths は、指標の参照実装と合否の場所として `Assets/Yurecheck/Runtime/Measure/*Reference*.cs` と `Assets/Yurecheck/Runtime/Judge/**` を挙げている。他の3か所は、docs/adr/0018 で移った先の `core/Yurecheck.Core/Measure/*Reference*.cs` と `core/Yurecheck.Core/Judge/*.cs` を挙げている。
2. settings.dev.json の deny が role_paths.json より広い箇所が2つある。1行目は環境の範囲、2行目はメンテナが書くファイルの食い違いである。

| deny | role_paths.json |
|---|---|
| `Packages/**` | `Packages/manifest.json`、`Packages/packages-lock.json` |
| `core/Yurecheck.Core/Judge/**` | `core/Yurecheck.Core/Judge/*.cs` |

## なぜ

1 が残っていると、AI が core/ の参照実装や合否のファイルを触っても owner-written.md の rule は文脈に入らない。書き込みは deny と guard が止めるが、「読んで提案する」という扱いの指示は届かない。

2 は ops.md の「settings の deny は .claude/role_paths.json と同じ内容を保つ」に反している。deny が広い側にずれているので、今は守りが抜けているわけではない。ただ、どちらが正しい範囲なのかが読み手に分からない。

## 確かめた方法(2026-10-10、feat/2-verify-hooks の badd3f1、dev の役割)

- 1 は、owner-written.md の frontmatter と、docs/OWNER_WRITTEN.md の表、role_paths.json の owner_written を目で比べた。`Assets/Yurecheck/Runtime/` と `core/Yurecheck.Core/` は、どちらもまだリポジトリに無い。
- 2 は、settings.dev.json の deny のうち `Edit(...)` のパスと、role_paths.json の owner_written と env_only を集合で比べた。`.claude/*` と `.claude/**` のように glob の書き方だけが違うものは、同じ範囲として扱った。
- settings.env.json の deny は比べていない。

## 受け入れの条件

- メンテナが書くファイルについて、上に挙げた場所がすべて同じパスの集合を指している。
- 環境の範囲について、role_paths.json の env_only と、settings.dev.json の deny からメンテナが書くファイルの分を除いたものが、同じパスの集合を指している。
- 2つの集合がそれぞれ揃っていることを確かめるテストが tools/tests/ にある。設計を進めて範囲が変わったときに、ずれが残らないようにするため。

## 補足

メンテナは、運用面の修正が済んだら設計を本格的に進める予定である。そのときに範囲を設定し直す見込みがあるので、この提案はその作業と一緒に扱ってよい(2026-10-10 メンテナ)。

# 公開前の検査をすり抜けられないようにする

## 要件

commit と push の前の検査(commit ゲート、pre-commit、tools/commit.py。本体は tools/guardlib.py)が、次の形でも秘密を止めるようにする。

1. **commit の検査は、インデックスに入る中身を見る。** 鍵をステージした後に作業ツリーを無害に戻しても、作業ツリーからファイルを消しても止める。
2. **push の検査は、送るコミットの履歴をすべて見る。** 鍵を入れたコミットの後に消すコミットを積み、正味の差分から鍵が消えていても止める。
3. **除外の場所でも、秘密ファイルの名前と鍵の形の文字列は止める。** 今は `tools/`、`.claude/hooks/`、`docs/handoff/` の下を、名前の検査も含めて丸ごと飛ばしている。除外が要るなら、除外する理由のあるファイルと検査の種類に絞る。
4. 止めすぎない。普通のファイルは今どおり通す。

次の2点は、止めるかどうかを環境の役割が決める。決めたら、どちらに決めたかと理由を docs/ops/ に残す。

- テキストとして読まないファイルの中身。先頭 4KB に NUL があるファイル、UTF-16 のテキスト、LFS の拡張子(`.png`、`.unitypackage` など)のファイルは、今は中身を走査しない。
- 名前のパターンに入っていない秘密ファイル。`id_dsa`、`*.keystore`、`*.ppk`、`.netrc`、`credentials.json`、`service-account.json` は、今は通る。

## なぜ

AGENTS.md は「鍵の形をした文字列、.env や鍵のファイルは入れない。止めるのは commit と push の前のゲート」と決めている。公開リポジトリなので、一度 push した鍵は履歴から消しても回収できない。

1 から 3 は、わざと避けなくても普段の作業で起こりうる。

- ステージした後にファイルを直すのは、よくある手順である。
- 鍵を入れてしまったコミットを、次のコミットで消して直したつもりになることもある。
- `tools/` は環境の役割が日常的に書く場所である。

## 再現(2026-10-10、feat/2-verify-hooks の 0a3a2b6、dev の役割、Windows 11)

このブランチを scratchpad に clone し、`core.hooksPath .githooks` を設定して試した。鍵の形の文字列は、実行時に組み立てた `AKIA` で始まる 20 文字を使った。

今の検査で止まるもの:

- 名前で止めるもの(13件): `.env`、`.env.local`、`config/.env`、`.ENV`、`*.pem`、`*.key`、`*.p12`、`*.pfx`、`*.jks`、`id_rsa`、`id_ed25519.pub`、`id_ecdsa`、`*.secret`
- 中身で止めるもの(11件): 秘密鍵のヘッダ、`ghp_`、`github_pat_`、`gho_`、`sk-`、`AKIA`、`xoxb-`、password への代入、api_key の指定、JSON の token、`.cs` の中の `secret=`
- 大きさで止めるもの: 11MB の `.bin`。2MB を超えるテキストは「未検査」として止まった。

すり抜けたもの(commit ゲートと pre-commit がどちらも通した):

| 形 | 結果 |
|---|---|
| ステージした後、作業ツリーを無害に戻す | 通した |
| ステージした後、作業ツリーから消す | 通した |
| 鍵を入れたコミットと、消すコミットを続けて作り、`git push` をゲートに渡す | 通した |
| `tools/leak.txt` に鍵を書く。`git add -f tools/.env` | 通した |
| `.claude/hooks/` と `docs/handoff/` の下に鍵を書く | 通した |
| NUL の後ろに鍵を書く。UTF-16 で鍵を書く | 通した |
| `.png` と `.unitypackage` の中身に鍵を書く | 通した |
| `id_dsa`、`*.keystore`、`*.ppk`、`.netrc`、`credentials.json`、`service-account.json` | 通した |

guardlib.py を読んだうえでの判断は次のとおりである。

- `scan` は `os.path.join(root, rp)` で作業ツリーのファイルを開いている。ファイルが無ければ飛ばす。
- push のときは `git diff --name-only @{upstream}...HEAD` の正味の差分のファイル名だけを見ている。
- `SKIP_PREFIX` に当たるパスは、名前の検査より前に `continue` している。

## 受け入れのテスト

tools/tests/ に置く想定である(dev は書けないので、本文をここに置く)。tools/tests/conftest.py の `tmp_repo`、`run_hook`、`run_tool`、`git` を使う。

2026-10-10 に feat/2-verify-hooks(0a3a2b6)で回すと「7 failed, 2 passed」だった。止める側の 7 件が失敗するので、すり抜けを再現できている。通った 2 件のうち、`test_plain_staged_secret_is_blocked` は判定の土台が正しいことを、`test_clean_file_passes` は止めすぎないことを確かめている。

要件の後半の2点(テキストとして読まないファイル、名前のパターンの範囲)にはテストを付けていない。どちらに決めるかで期待が変わるためである。

```python
import pytest
from conftest import git, run_hook, run_tool

GATE = ".claude/hooks/pretooluse_commit_gate.py"
KEY = "AK" + "IA" + "Q" * 16  # 鍵の形。ファイルに鍵の形を残さないため実行時に組み立てる


def bash(repo, command):
    return {"tool_name": "Bash", "tool_input": {"command": command}, "cwd": str(repo)}


def blocked(repo):
    """commit ゲート(exit 2)と pre-commit の本体(exit 1)の両方が止めるか。"""
    g = run_hook(repo, GATE, bash(repo, "git commit -m t"), "dev")
    p = run_tool(repo, "tools/precommit.py", [])
    return g.returncode == 2 and p.returncode == 1


def stage(repo, name, data):
    (repo / name).parent.mkdir(parents=True, exist_ok=True)
    (repo / name).write_bytes(data if isinstance(data, bytes) else data.encode("utf-8"))
    git(repo, "add", "-f", name)


# 1. インデックスの中身を見る
def test_staged_secret_with_clean_worktree_is_blocked(tmp_repo):
    stage(tmp_repo, "leak.txt", KEY + "\n")
    (tmp_repo / "leak.txt").write_text("clean\n", encoding="utf-8")
    assert blocked(tmp_repo)


def test_staged_secret_deleted_from_worktree_is_blocked(tmp_repo):
    stage(tmp_repo, "leak.txt", KEY + "\n")
    (tmp_repo / "leak.txt").unlink()
    assert blocked(tmp_repo)


# 2. push は履歴を見る
def test_push_blocks_secret_added_then_removed(tmp_repo, tmp_path_factory):
    remote = tmp_path_factory.mktemp("remote")
    git(remote, "init", "-q", "--bare")
    git(tmp_repo, "remote", "add", "origin", str(remote))
    git(tmp_repo, "push", "-q", "-u", "origin", "main")
    stage(tmp_repo, "leak.txt", KEY + "\n")
    git(tmp_repo, "commit", "-q", "--no-verify", "-m", "leak")
    git(tmp_repo, "rm", "-q", "leak.txt")
    git(tmp_repo, "commit", "-q", "--no-verify", "-m", "remove")
    r = run_hook(tmp_repo, GATE, bash(tmp_repo, "git push"), "dev")
    assert r.returncode == 2


# 3. 除外の場所でも、秘密ファイルの名前と鍵の形は止める
@pytest.mark.parametrize("name,data", [
    ("tools/.env", "X=1\n"),
    (".claude/hooks/x.pem", "x\n"),
    ("tools/leak.txt", KEY + "\n"),
    ("docs/handoff/x.md", KEY + "\n"),
])
def test_skip_prefix_does_not_hide_secrets(tmp_repo, name, data):
    stage(tmp_repo, name, data)
    assert blocked(tmp_repo)


# 4. 今も止まる形(判定の土台が正しいことの確認)と、止めすぎないこと
def test_plain_staged_secret_is_blocked(tmp_repo):
    stage(tmp_repo, "leak.txt", KEY + "\n")
    assert blocked(tmp_repo)


def test_clean_file_passes(tmp_repo):
    stage(tmp_repo, "ok.txt", "hello\n")
    assert not blocked(tmp_repo)
    g = run_hook(tmp_repo, GATE, bash(tmp_repo, "git commit -m t"), "dev")
    assert g.returncode == 0
```
